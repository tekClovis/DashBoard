# Stack

| Layer | Choice | Why |
|---|---|---|
| Backend | NestJS + Prisma | Modules map 1:1 to services, so `/about.json` and widget routes stay organized as the service count grows. `@nestjs/passport`, `@nestjs/jwt` and `@nestjs/schedule` cover auth and the Timer without extra libraries; `@nestjs/serve-static` serves the built frontend from the same origin as the API; `@nestjs/throttler` rate-limits REST routes; `class-validator`/`class-transformer` validate DTOs, including widget params against their `ParamSpec`. `prisma`/`@prisma/client` is the ORM (stronger typing than TypeORM, thicker Nest ecosystem than Drizzle). TypeScript end to end lets widget param types be shared with the frontend. |
| Frontend | React + Vite | Largest ecosystem for the two hard UI problems here: a draggable widget grid (`react-grid-layout`) and accessible modals for widget config (Radix/shadcn). `@tanstack/react-query` caches REST server state (catalog, dashboards, instances); `socket.io-client` receives Timer pushes and writes them into that same cache, so there is no `refetchInterval` — the Timer, not the client, drives refresh. |
| Styling & UI | Tailwind CSS + shadcn/ui | Tailwind's responsive variants (`sm:`, `md:`) satisfy the responsive-UI requirement quickly. shadcn/ui is copied into the repo, not installed as a live package, so there is no supply-chain drift; it only pulls in small, stable Radix primitives for accessible dialogs and menus. |
| Widget grid | react-grid-layout | Drag, resize and responsive breakpoints out of the box, and the resulting layout is a plain JSON array that saves per user in the database. Add explicit move buttons alongside it for keyboard/screen-reader access. |
| Database | PostgreSQL + Redis | Postgres models users → linked accounts → widget instances relationally, with a JSONB column for each widget's params. `ioredis` is the Redis client; Redis caches upstream API responses per `(service, params, connection)` so free-tier quotas (25/day, 10k units/day, etc.) survive multiple users and refresh cycles without leaking one user's cached response to another. |
| Auth | Passport.js + @nestjs/jwt + bcrypt + Nodemailer | Passport's local strategy covers credential login (required by the subject); `nodemailer` sends the confirmation email (via Mailpit in dev). `passport-github2` and `passport-google-oauth20` back GitHub/Google login; those same strategies, plus `passport-steam`, back widget OAuth as a separate connect flow with its own callback and token storage, so login scope stays minimal. `@nestjs/jwt` signs session tokens; bcrypt avoids the native-build overhead argon2 adds to the Docker image. |
| Timer | Server tick loop + WebSocket | One interval walks an in-memory set of widget instances with at least one subscribed socket, matching the subject's "each widget communicates its refresh rate to the Timer" literally, without a per-tick database scan. `socket.io`/`@nestjs/websockets`/`@nestjs/platform-socket.io` push results to the browser over a room per widget instance; `socket.io-client` (frontend) subscribes/unsubscribes as widgets mount and unmount. |
| Services (defaults) | Open-Meteo, GitHub (core); Steam, YouTube (stretch) | No-key or free-key services chosen to clear (1+X) services and (3×X) widgets for a solo project (X = 1 → 2 services, 3 widgets). Core ships 2 services / 5 widgets; stretch brings it to 4 / 10. GitHub is also a login provider, via a separate flow from its widget OAuth. None need a card or paid plan. |
