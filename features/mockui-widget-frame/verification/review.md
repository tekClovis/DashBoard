   - **Result:** A reads "No results for “Atlantisxq”." ([07-session-a-invalid-city-copy--light-1440.png](https://github.com/tekClovis/dashBoard/blob/feature/mockui-widget-frame/features/mockui-widget-frame/verification/07-session-a-invalid-city-copy--light-1440.png?raw=true)). Check the city name." above "Last data from 00:27 · London, United Kingdom" ([08-session-b-invalid-city-names-paris--light-1440.png](https://github.com/tekClovis/dashBoard/blob/feature/mockui-widget-frame/features/mockui-widget-frame/verification/08-session-b-invalid-city-names-paris--light-1440.png?raw=true)). Paris is neither the city that was rejected nor the city of the data shown.
   - **Cause:** `WidgetFrame.tsx` builds the copy from `instance.params.city`, which is B's cached `['widgets']` entry. That entry is from before A's Configure. The server's `widget:error` message carries the rejected city ("Could not resolve city 'atlantisxq'."), but the frame ignores it. This is the same stale-params path that 47e40f9 fixed for history, here reaching the error copy.
   - Otherwise correct: the copy for every code matches design-reference §5 and the mock's `ERR_COPY`. **Connect GitHub** and **Reconnect GitHub** link to `/services`. The band's **Configure** opens the dialog, and saving a valid city brings the panel back to live in both sessions. 7. **Note** (spec Constraints, outside the numbered checklist): commits a2f99b2 and 47e40f9 change `server/src/timer/*` and `shared/src/socket.ts`, and add an optional `paramsKey` to `widget:data`. The spec says "No server, `shared/` or API contract changes", and the §5 table says the history is kept client-side "(no API change)". This is a constraint breach, not a checklist miss, and it is close to necessary.
   - Without a2f99b2, the server kept fetching the old params while any subscriber stayed, so Configure did not take effect. That breaks the item 3 Configure flow.
   - Without 47e40f9, a second session has no signal that the params changed, so item 4 fails. The `instance.updated` event in `dashboard-events.ts` is never forwarded to clients.
   - The field is additive and optional, and the docs were updated. It still needs the spec owner's sign-off.
   - Other notes: B's Configure dialog still opens with B's stale params until `['widgets']` refetches on window focus. A Configure that only changes the refresh rate is ignored by `TimerService.activate` (same params means no-op), so the frame's stale threshold uses the new rate while the server keeps the old one.
