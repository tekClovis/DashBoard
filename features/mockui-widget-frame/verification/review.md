4. **FAIL**: The push history now survives a remount: Services → Home took the sparkline to 4 points ([02](https://github.com/tekClovis/dashBoard/blob/feature/mockui-widget-frame/features/mockui-widget-frame/verification/02-sparkline-survives-remount--light-1440.png?raw=true)). It also resets when the remount comes after an out-of-band `PATCH` ([03](https://github.com/tekClovis/dashBoard/blob/feature/mockui-widget-frame/features/mockui-widget-frame/verification/03-history-reset-after-city-change--light-1440.png?raw=true)). It still mixes cities after a change made through the real Configure dialog.
   - **Steps:** the current_weather city was Reykjavik. It was changed to Paris with Configure → Save, which sends `PATCH /api/widgets/:id` and invalidates `['widgets']`. Then the next scheduled push was awaited, and the view was remounted (Services → Home).
   - **Result:** the panel's channel reads "Paris, France", but the sparkline shows Reykjavik 10° and then Paris 20°, with "↑ 10.0° since 14:25" ([11](https://github.com/tekClovis/dashBoard/blob/feature/mockui-widget-frame/features/mockui-widget-frame/verification/11-sparkline-mixes-cities-after-configure--light-1440.png?raw=true), [12](https://github.com/tekClovis/dashBoard/blob/feature/mockui-widget-frame/features/mockui-widget-frame/verification/12-live-pulse-frozen-mid-sweep--light-1440.png?raw=true)).
   - **Cause:** `useWidgetData` tags each push with the params the client holds *when the push arrives* (`paramsKey.current`), not the params the data was fetched with. The server's timer is not reconfigured on PATCH, so it keeps fetching the old city until the client resubscribes. `useWidgetData` deliberately does not resubscribe on a params change. The first push after Save therefore carries Reykjavik data under the Paris key. It resets the history to that point, and the Paris push after the resubscribe is appended to it. `github.pull_requests` uses the same `pushTrail`, so its "↑N since" can compare two repos or two `state=` filters in the same way.
   - No spec covers this sequence: the new `useWidgetData.spec` case changes params and pushes new-params data in the same step. Channel, stat and detail, plus mono numbers, times and IDs, are otherwise correct for each renderer. Note: the current-weather stat has no condition icon, and forecast rows have no per-day icon, unlike the mock.

7. **PASS** (mock flow "Simulate a push", design-reference §5 "Live pulse"): the pulse CSS compiles in the Vite build. That build has the `widget-sweep`, `widget-ping` and `widget-sweep-still` keyframes, and the `[data-pulse]>[data-slot=widget-head]:after` rule. In the browser, a `MutationObserver` on the live dashboard saw `data-pulse` set on each `widget:data` and cleared after about 900 ms. The computed styles were `widget-sweep 0.9s` on the header `::after` with an `oklch(0.62 0.18 148)` (`--live`) background, and `widget-ping` on the live lamp. With reduced motion, the line uses `widget-sweep-still` and the lamp has no animation. A frame frozen mid-pulse shows the lamp ring and the line under the header ([12](https://github.com/tekClovis/dashBoard/blob/feature/mockui-widget-frame/features/mockui-widget-frame/verification/12-live-pulse-frozen-mid-sweep--light-1440.png?raw=true)).
